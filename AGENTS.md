# Development

- Use `nix develop path:.` for the Android toolchain. Build Android only for `arm64-v8a`.
- Keep React Native UI and browser integration shared between Android and iOS. Transcript validation, parsing, normalization, search, export, and persistence belong in `core/` (Rust).
- Media format validation/planning, SponsorBlock parsing, settings/history storage, and bounded-range streaming also belong in Rust. Platform adapters provide HTTPS byte requests and MP4 remuxing; Expo Video owns playback, background audio, and PiP.
- `npm ci` generates the injected player decoder. Run `npm run page:build` after changing `scripts/player-decoder.js`, `scripts/media-token.js`, or `scripts/page-trust.js`. The bundled decoder runs only inside YouTube's page runtime.
- Evaluate extracted signature code only in `PlayerRuntime`, a network-disabled renderer separate from YouTube's page and the React Native runtime. Correlate every evaluation with the pending media request; return only signature strings. Do not use Android WebView's `incognito` prop here: it clears cookies for all WebViews.
- Android builds `expo-video` from source to include `scripts/patch-video.ts`; keep the autolinking override and postinstall patch together. Expo's prebuilt binary does not include local source fixes.
- `modules/govue-core` is a local Expo module with small Kotlin and Swift adapters around the same UniFFI JSON function. Generated bindings and compiled libraries are ignored; regenerate with `npm run core:android` or `npm run core:ios` rather than editing them.
- iOS builds require an Apple Silicon Mac with Xcode. Use `npm run ios` or `npm run prebuild:ios` so the Rust XCFramework exists before CocoaPods runs. Keep Nix's host SDK/compiler environment out of Xcode builds.
- This is a separate app from `../herdr-android`; keep its identifiers, dependencies, and data independent.
- Keep the WebView mounted while the transcript reader is open. Keep its initial `source` stable across in-page navigation.
- Embed online native playback over the page's reported video bounds so comments and recommendations remain interactive. Validate and correlate layout messages; yield the native surface when YouTube panels cover that area. Keep Android's texture surface for clipping and opacity, and keep one mounted VideoView across layout changes.
- Keep injected code self-contained in `src/youtube/pageBridge.js`; it executes in a different JavaScript runtime. Do not interpolate unescaped page content into executable code.
- Treat WebView messages as untrusted. Validate origins and correlate responses to the active request and video. Cancel pending work on navigation.
- Get the feature working live before writing new tests. Then run `npm run check` and `npx expo install --check` after relevant changes. Checks include the Rust boundary/cache tests and injected browser behavior. Live device verification is separate from fixture tests.
- Keep normalized transcript cache data in the native sandbox. Signed caption URLs, session tokens, and raw responses must stay out of persistent storage.
- Signed media URLs may cross into native memory for playback/downloads; never persist or log them. The media proxy binds only to loopback and exposes opaque, scoped routes. Keep plain HTTP restricted to loopback.
- Native `android/` and `ios/` projects are generated by Expo prebuild and ignored; put persistent configuration in `app.json` or a config plugin.
- Use `uv` if Python is needed.
- use ../whip as engineering reference.
- Make a feature work on Android first before testing iOS
- React Native for presentation and Rust core for logic and state
