# Development

- Use `nix develop path:.` for the Android toolchain. Build Android only for `arm64-v8a`.
- Keep React Native UI and browser integration shared between Android and iOS. Transcript validation, parsing, normalization, search, export, and persistence belong in `core/` (Rust).
- `modules/lingoplay-core` is a local Expo module with small Kotlin and Swift adapters around the same UniFFI JSON function. Generated bindings and compiled libraries are ignored; regenerate with `npm run core:android` or `npm run core:ios` rather than editing them.
- iOS builds require an Apple Silicon Mac with Xcode. Use `npm run ios` or `npm run prebuild:ios` so the Rust XCFramework exists before CocoaPods runs. Keep Nix's host SDK/compiler environment out of Xcode builds.
- This is a separate app from `../herdr-android`; keep its identifiers, dependencies, and data independent.
- Keep the WebView mounted while the transcript reader is open. Keep its initial `source` stable across in-page navigation.
- Keep injected code self-contained in `src/youtube/pageBridge.js`; it executes in a different JavaScript runtime. Do not interpolate unescaped page content into executable code.
- Treat WebView messages as untrusted. Validate origins and correlate responses to the active request and video. Cancel pending work on navigation.
- Get the feature working live before writing new tests. Then run `npm run check` and `npx expo install --check` after relevant changes. Checks include the Rust boundary/cache tests and injected browser behavior. Live device verification is separate from fixture tests.
- Keep normalized transcript cache data in the native sandbox. Signed caption URLs, session tokens, and raw responses must stay out of persistent storage.
- Native `android/` and `ios/` projects are generated by Expo prebuild and ignored; put persistent configuration in `app.json` or a config plugin.
- Use `uv` if Python is needed.
